1. DATASET
--------------------------------------------------------------------------------

The dataset used is cars.csv, a structured CSV file containing specifications
for hundreds of Indian passenger vehicles. Prior to any processing, the raw
dataset contains 120+ feature columns covering engine specs, body dimensions,
safety ratings, fuel type, transmission, pricing, and more.

Target Variable:
  - Ex-Showroom_Price: The base on-road price of the vehicle (in INR).
    This column is used to derive the "Budget_Class" (Low, Mid, High) label
    used for supervised classification.


--------------------------------------------------------------------------------
2. DATA CLEANING
--------------------------------------------------------------------------------

Module : src/data_loader.py
Class  : DataLoader

The data cleaning phase is handled inside the DataLoader class. The following
specific techniques were applied:

  a) Removal of Index Column
     - The "Unnamed: 0" column auto-generated by Pandas CSV reads is
       automatically detected and dropped.

  b) Currency String Cleaning  (Method: clean_currency)
     - The Ex-Showroom_Price column contains values formatted as currency
       strings (e.g., "Rs. 5,60,000"). These are processed by:
         * Stripping the "Rs." prefix
         * Removing all comma separators
         * Converting the result to float using pd.to_numeric()
     - Rows where the price cannot be parsed (NaN after coerce) are dropped.

  c) Numeric Extraction from Mixed Strings  (Method: extract_numeric)
     - Many specification columns contain values with units embedded in them,
       for example: "1197 cc", "88.50 bhp", "15.5 kmpl".
     - A regular expression pattern r"(\d+\.?\d*)" is applied using
       str.extract() to peel the numeric part out of these mixed strings.
     - After extraction, each column is converted to float using pd.to_numeric().

  d) Dynamic Column Detection
     - Instead of hardcoding specific column names to clean, the system
       dynamically scans all columns in the dataframe and applies the numeric
       extraction to any column that meets a numeric-content threshold
       (more than 10% of its rows start with a digit).
     - This ensures we do not miss any numeric specification column regardless
       of the dataset structure.

  e) Mileage Column Resolution
     - The mileage information may exist under different column names depending
       on the dataset version (e.g., "City_Mileage" or "ARAI_Certified_Mileage").
     - The system tests for each known column name in order of priority and
       extracts the numeric mileage value accordingly.
     - If no mileage column exists, a fallback formula estimates mileage from
       engine displacement: Mileage = 25 - (Displacement / 200), clipped
       between 5 and 25 kmpl.

  f) Critical Row Dropping
     - Any row missing values in Displacement, Power, or Mileage is dropped,
       as these are the core anchors for the ranking stage.

  g) Median Imputation
     - After the initial cleaning, any remaining NaN values in the four primary
       ranking features (Mileage, Seating_Capacity, Power, Displacement) are
       filled in using the median value of each respective column. Median is
       preferred over mean as it is robust to outliers in vehicle specs.


--------------------------------------------------------------------------------
3. DATA PREPROCESSING
--------------------------------------------------------------------------------

Module : src/models.py
Class  : VehicleClassifier (inside _prepare_data method)

Preprocessing transforms raw cleaned data into a format suitable for machine
learning. The preprocessing is structured as a Scikit-Learn ColumnTransformer
with two parallel sub-pipelines:

  a) Numerical Feature Preprocessing Pipeline
     Input  : All float/int64 columns (dynamically detected via select_dtypes)
     Steps  :
       1. SimpleImputer (strategy='median')
          - A second safety pass to fill any residual NaN values in numerical
            columns using the median of that column.
       2. MinMaxScaler
          - Each numerical feature is scaled to the range [0, 1] using the
            formula: X_scaled = (X - X_min) / (X_max - X_min).
          - This normalisation is critical for the Cosine Similarity ranking
            stage so that high-value columns (e.g., price in lakhs) do not
            dominate low-value columns (e.g., number of gears).

  b) Categorical Feature Preprocessing Pipeline
     Input  : All object/category dtype columns with fewer than 30 unique values
              (high-cardinality columns like car variant names are excluded
               programmatically to prevent one-hot-encoding explosion)
     Steps  :
       1. SimpleImputer (strategy='most_frequent')
          - Missing categorical values are filled in with the most commonly
            occurring value in that column (mode imputation).
       2. OneHotEncoder (handle_unknown='ignore')
          - Each categorical feature (e.g., Fuel_Type: Petrol, Diesel, CNG) is
            converted into binary indicator columns (one per category).
          - handle_unknown='ignore' ensures unseen categories at prediction time
            do not cause errors.

  c) Budget Class Label Creation
     - After cleaning but before model training, the target variable is created
       using Pandas qcut() on the Ex-Showroom_Price column.
     - qcut() divides the price range into 3 equal-frequency quantile bins,
       assigning the labels: "Low", "Mid", "High".
     - This ensures each budget class has approximately the same number of
       samples (balanced classes), improving model performance.

4. FEATURE REDUCTION
--------------------------------------------------------------------------------

Module : src/models.py
Class  : VehicleClassifier (inside train method, embedded in Pipeline)

Feature reduction is performed algorithmically using two stacked methods
embedded in the Scikit-Learn machine learning Pipeline, before data reaches
the final prediction model.

  The raw dataset starts with 120+ columns.
  After cleaning and one-hot encoding: ~219 processed features.
  After feature reduction: 99 retained features.

  a) Step 1 - VarianceThreshold
     Algorithm  : sklearn.feature_selection.VarianceThreshold
     What it does:
       - Scans every feature column and computes its statistical variance
         (the spread of values across all samples).
       - Any column with a variance of exactly 0.0 is automatically removed.
         A variance of 0 means every car in the dataset has the exact same
         value for that feature, making it completely uninformative for any
         classifier. For example, a column "Airbags_Mandatory = True" that is
         True for every single car would be eliminated.
     Why it was used:
       - It is a zero-cost, purely statistical computation that eliminates
         pure noise with no risk of removing genuinely useful features.

  b) Step 2 - SelectFromModel (with Random Forest Classifier as estimator)
     Algorithm  : sklearn.feature_selection.SelectFromModel
     Estimator  : RandomForestClassifier(n_estimators=50, random_state=42)
     Threshold  : 'median'
     What it does:
       - An internal Random Forest model (50 decision trees) is trained on all
         the features remaining after VarianceThreshold.
       - After training, the Random Forest's internal "Gini Importance" (also
         called Mean Decrease in Impurity) is computed for every feature.
         Gini Importance measures how much each feature contributes to reducing
         prediction uncertainty across all 50 trees.
       - The threshold='median' setting discards the bottom 50% of features by
         importance score, keeping only those features whose importance is above
         the median importance value.
       - Only the surviving features are passed to the final prediction model.
     Why it was used:
       - SelectFromModel performs data-driven, mathematically principled feature
         elimination. It does not rely on domain intuition; instead, the Random
         Forest itself determines which technical specifications (e.g., Kerb
         Weight, Displacement, Gears, Ground Clearance) are genuinely predictive
         of the budget tier.

  Accuracy After Feature Reduction:
    - We use a strict evaluation protocol (Stratified 5-Fold Cross-Validation)
      to avoid test-set data leakage. The budget bins are learned only from the
      training fold and applied to the test fold.
    - This ensures that our feature reduction and Random Forest model report
      realistic generalization accuracy, cleanly separating the "evaluation"
      phase from the "production/app" phase where we train on all data.

5. MACHINE LEARNING MODELS
--------------------------------------------------------------------------------

Module : src/models.py
Class  : VehicleClassifier

Two machine learning models are trained for Stage 1 (Classification/Filtering):

  a) Random Forest Classifier  [Primary Model]
     Algorithm     : sklearn.ensemble.RandomForestClassifier
     Parameters    : n_estimators=200, random_state=42
     Task          : Classify each vehicle into "Low", "Mid", or "High" budget.
     Why RF was used:
       - An ensemble of 200 decision trees votes collectively, making it highly
         robust and resistant to overfitting.
       - It naturally handles non-linear relationships between specs and price.
       - It provides a built-in feature_importances_ attribute, which powers the
         SelectFromModel feature reduction step above.

  b) CART Decision Tree  [Explainability Model]
     Algorithm     : sklearn.tree.DecisionTreeClassifier
     Parameters    : max_depth=4, random_state=42
     Task          : Classify vehicles into budget classes with a white-box model.
     Why CART was used:
       - The Decision Tree is a single, shallow, human-readable tree.
       - Its structure (if Displacement > 1500 AND Body_Type = SUV, then High)
         can be exported as text rules and shown to stakeholders.
       - max_depth=4 prevents the tree from growing too complex and ensures the
         rules remain interpretable.

  Full Training Pipeline (both models follow this):
    Preprocessor (ColumnTransformer)
        --> VarianceThreshold
            --> SelectFromModel (RF feature selector)
                --> Final Classifier (RF or CART)

6. RECOMMENDATION ENGINE - STAGE 2: RANKING
--------------------------------------------------------------------------------

Module : src/recommender.py
Class  : VehicleRecommender

After Stage 1 filters the dataset to only show cars in the correct budget tier,
Stage 2 ranks the remaining candidates to find the best personal match.

  Algorithm : Cosine Similarity
  Library   : sklearn.metrics.pairwise.cosine_similarity

  What it does:
    - Each car's specification profile is treated as a vector in a
      multi-dimensional space: [Mileage, Seating_Capacity, Power, Displacement].
    - The user's preference profile (derived from lifestyle mapping) is similarly
      expressed as a vector of the same four dimensions.
    - Cosine Similarity computes the angle between each car vector and the user
      vector. An angle of 0° (similarity = 1.0) means a perfect match; a large
      angle (similarity near 0.0) means a poor match.
    - Cars are ranked in descending order of similarity score.

  Why Cosine Similarity:
    - Unlike Euclidean distance, cosine similarity focuses on the profile/shape
      of a car's specs relative to the user's needs, not the absolute scale.
    - A budget hatchback matching perfectly in its class scores higher than a
      luxury car that is far off in profile, even if the luxury car has more raw
      power, because the angle between vectors is what is measured.

  Pre-scaling: Before similarity calculation, both the candidate cars and the
  user vector are scaled using MinMaxScaler on the filtered candidate pool,
  ensuring all four features are on the [0, 1] range.

7. LIFESTYLE-TO-SPECIFICATION MAPPING
--------------------------------------------------------------------------------

Module : src/recommender.py
Method : map_lifestyle_to_specs()

This module bridges the gap between user-friendly UI inputs and technical
vehicle specifications. The user never sets raw numbers; they answer conceptual
questions. The mapping layer translates their answers:

  Usage (Dropdown) --> Mileage Priority + Power Level
    - "City Commute"          --> Mileage: 18 kmpl, Power: 70 BHP
    - "Highway/Long Distance" --> Mileage: 15 kmpl, Power: 100 BHP
    - "Off-roading"           --> Mileage: 10 kmpl, Power: 120 BHP, Body: SUV
    - "Family Trips"          --> Mileage: 14 kmpl, Power: 90 BHP

  Passengers (Slider) --> Seating Capacity + Body Type
    - "5+"                    --> Seats: 7, Body Type preference: SUV

  Experience (Radio) --> Power Cap
    - "First-time Buyer"      --> Power capped at 90 BHP maximum

  Priority (Dropdown) --> Final Weight Adjustment
    - "Fuel Efficiency"       --> Mileage boosted to 20 kmpl minimum
    - "Performance"           --> Power boosted to 120 BHP minimum
